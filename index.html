An agent should be able to say what it is allowed to do.

Almost none can. We looked in two places, and found the same gap in both.

2.3%103 of 4,445

Tools we found by reading 200 public agent codebases. Only these say whether they change anything — write, send, spend or delete. The other 4,342 say nothing either way, so nobody can tell from the code which ones are safe to run unattended.

Entries in the largest public registry of agent declarations, counted until the listing ran out. Every entry records which package to run and where to reach it. The registry has no field for what the agent may do. Not one that is usually left empty — there is nowhere to put it.

What this is

PRIVI — production readiness for agentic systems. Two things, and they are both public.

A list of 41 checks for an AI agent going into production: whose identity it acts under, what it can destroy, who approved that, and how you would know afterwards. 20 of them can be read straight from a repository. 21 cannot, and the list says which, rather than pretending a scanner settles them.

And the tooling that reads them: it takes the written statement of what an agent is allowed to do, compares it against what the code actually does, and reports the difference. When the two disagree, the code wins the argument and the disagreement is the finding.

The list is a draft and says so in its own text. No second party has applied it without us. Until that happens it is a rubric with a version history rather than a standard, and it carries that sentence rather than burying it.

Why the second release is the hard one

An agent you cannot describe is an agent you cannot approve. An agent you cannot describe after it changed is one you cannot approve twice.

A review answers a question about one particular day. Then the agent ships again on Thursday, and by the second month nobody can say which findings still hold. The usual answer is to re-run the whole review, which costs more than most teams will pay more than once.

So the tooling answers the narrower question instead: this release changed these things; here is what each one breaks, which approvals stopped being valid, and which survived untouched. Approvals survive by name, not by still looking fine.

  • The declaration said read-only; the TypeScript could send. The declaration never changed — the code did.
  • One agent, two versions of its declaration. Five named changes, and the cost of each.
  • Evidence produced by running the thing, rather than asserted — the same agent hardened and unsafe, and what a local test genuinely cannot establish.
